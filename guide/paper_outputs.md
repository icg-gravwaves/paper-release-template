# Writing outputs the paper can use

Many journals require a flat source directory and a single `.tex` file at
submission. So figures are saved directly into `paper/`, next to
`main.tex`, and tables and numbers are printed by the notebooks for pasting
into `main.tex`. The paper can then be uploaded as-is.

## Figures

```python
from common import paths

paths.use_paper_style()
fig, ax = plt.subplots()
...
paths.save_paper_figure(fig, "figure_1_measurements")
```

writes `paper/figure_1_measurements.pdf` and `.png`. In LaTeX:

```latex
\includegraphics[width=\columnwidth]{figure_1_measurements.pdf}
```

`paper.mplstyle` sets the default figure size to a single journal column
(3.25 × 2 inches), so fonts in the figure match the text at
`width=\columnwidth` with no rescaling. For a two-column figure, pass
`figsize=(6.75, 3)` and use `width=\textwidth`.

Prefer vector PDF for line plots. Use PNG (with `dpi=300`) for images or
plots with very many points, which would make a slow, large PDF.

## Tables

Journals often reject a source that `\input`s other `.tex` files, so a
table is never written to its own file. Instead the notebook prints the
`tabular` and you paste it into `main.tex`:

```python
paths.show_for_paper(table_tex, "the table environment for Table 1")
```

prints

```text
% ---- Copy this into the table environment for Table 1 of paper/main.tex ----
\begin{tabular}{c|cc|c}
...
\end{tabular}
% ---- end of block ----

Up to date: paper/main.tex already contains this block.
```

The last line says `NOT FOUND in paper/main.tex` when the paper holds an
older version of the table (comparison ignores indentation and blank
lines). Keep the `table` environment, caption and label in `main.tex` and
paste only the `tabular`, so co-authors can edit the caption on Overleaf.

## Numbers in the text

The notebook prints one `\newcommand` per value, to paste into the
preamble of `main.tex`:

```latex
% Generated by analysis/table_1_fit_results.ipynb -- do not edit by hand
\newcommand{\NGroups}{4}
\newcommand{\SteepestSlope}{$1.64 \pm 0.04$}
```

The text then uses `\NGroups{}` instead of `4`, so each number is pasted
once and every mention of it updates together. LaTeX macro names cannot
contain digits, so spell them out (`\NPointsPerGroup`, not
`\NPoints1`).

### If a journal asks for macros to be expanded

A preamble full of `\newcommand`s stays inside the single `main.tex`, so it
meets the no-separate-files rule. Some publishers' production teams
nevertheless ask authors to expand custom macros before typesetting. If
that happens, pass each value to `show_for_paper` on its own and type it
straight into the text:

```python
paths.show_for_paper(f"${m:.2f} \\pm {m_err:.2f}$", "the Results section")
```

The check looks for the value anywhere in `main.tex`, so CI still catches a
number that no longer matches the data (keep each value on one line of the
source). Unless a journal
asks, keep the macros: each number is then updated in exactly one place.

## Keeping the paper in step with the data

`.github/workflows/book.yml` rebuilds the site, which re-runs every
notebook, then searches the executed notebooks for `NOT FOUND in
paper/main.tex`. If the data or code changed and nobody pasted the new
table or numbers into the paper, the build fails and the notebook page
shows exactly what to paste.
